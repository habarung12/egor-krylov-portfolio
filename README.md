# Egor Krylov Portfolio — админ-панель

Существующий статический сайт и его изображения сохранены. Добавлены `admin.html`, `admin.js`, `supabase-config.js` и `supabase-setup.sql`. Динамические проекты/работы загружаются из Supabase, а старые проекты остаются на месте.

## Важно
Админка не заработает до настройки Supabase. В архиве нет секретов или ключей. Не добавляйте `service_role` key в браузерный код.

## Настройка бесплатного Supabase

1. Создайте проект на https://supabase.com/.
2. Откройте **SQL Editor**, вставьте содержимое `supabase-setup.sql` и запустите.
3. В **Authentication → Users** вручную создайте пользователя с вашим email и паролем.
4. Скопируйте UUID созданного пользователя и выполните в SQL Editor: `insert into public.portfolio_admins (user_id) values ('ВАШ-UUID') on conflict do nothing;`. Только эти аккаунты смогут менять контент.
5. В настройках Authentication отключите публичную регистрацию (Allow new users to sign up), чтобы посторонние не могли зарегистрироваться.
6. Откройте **Project Settings → API** (или Connect) и скопируйте Project URL и `anon`/publishable key.
7. В `supabase-config.js` замените `https://YOUR-PROJECT.supabase.co` и `YOUR-SUPABASE-ANON-KEY` своими значениями. Никогда не вставляйте `service_role`/secret key.
8. Загрузите все файлы из папки репозитория в GitHub. Публикуйте как обычно через GitHub Pages.

## Использование

- Админка: `https://habarung12.github.io/egor-krylov-portfolio/admin.html`
- Войдите по email и паролю, созданным на шаге 3.
- Создавайте разделы, меняйте их название/описание/цвета/порядок.
- Загружайте изображения в выбранный раздел; название можно изменить позже.
- Удаление раздела удаляет его записи и связанные загруженные изображения.
- Старые проекты/изображения остаются в статических файлах, как раньше.

## Ограничения текущей версии

- Новые загрузки поддерживают изображения, не видео.
- Переключатель RU/EN переводит интерфейс и существующие описания, запоминает выбор. Также доступны ссылки `?lang=en` и `?lang=ru`.
- Для новых проектов заполняйте название, дату и описание на двух языках. Для работ доступны названия RU/EN. Без английского перевода используется русский. Надписи внутри изображений не переводятся.
- Изменения новых разделов и работ сохраняются в Supabase, а не в `app.js`.
- Бесплатные лимиты Supabase могут меняться; проверьте актуальные ограничения своего проекта.

## Обновление уже настроенной версии
Повторно выполните `supabase-setup.sql`: он добавит поля EN и заменит старые широкие политики доступа. Затем добавьте UUID администратора в `portfolio_admins`, как описано выше. Существующие записи сохранятся.

## Проверка после публикации
1. Откройте сайт, переключите RU / EN, обновите страницу — выбранный язык должен сохраниться.
2. Откройте `admin.html`, войдите, создайте тестовый проект с текстами RU/EN.
3. Загрузите изображение, откройте сайт в другом браузере без входа — проект и работа должны быть видны.
4. Проверьте редактирование названия и удаление тестового проекта.
5. Аккаунт, не внесённый в `portfolio_admins`, не должен иметь права записи.

Админка управляет новыми проектами. Исходные девять разделов и их изображения остаются в `app.js` и `assets/works.js`. Порядок новых проектов задаётся внутри блока новых проектов, после исходных. Публикация изменений GitHub Pages и подключение Supabase требуют доступа к вашим аккаунтам. Без настройки подключения публичный сайт показывает исходное портфолио.
